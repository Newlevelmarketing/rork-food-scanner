## Phase 1 — Make it compile

**The repo does not build from a clean clone.** This is the first thing you will hit, and it looks
like a broken project rather than a missing file.

`ios-calzy/.gitignore:34` ignores `Config.swift`. It is generated by Rork and holds the AI
gateway settings. Two files reference it:

- `Services/NutritionAI.swift:90` → `Config.EXPO_PUBLIC_TOOLKIT_URL`
- `Services/NutritionAI.swift:184` → `Config.EXPO_PUBLIC_RORK_TOOLKIT_SECRET_KEY`

Nothing else in the iOS target uses `Config`. So you need exactly those two members.

### Create the file

Create **`ios-calzy/ModernBodyFoodScanner/Config.swift`** — that exact folder, alongside
`ContentView.swift`:

```swift
import Foundation

/// Rork-generated configuration. Gitignored - never commit real values.
enum Config {
    static let EXPO_PUBLIC_TOOLKIT_URL = "https://toolkit.rork.com"
    static let EXPO_PUBLIC_RORK_TOOLKIT_SECRET_KEY = "<paste the key from Rork>"
}
```

**You do not need to add it to the Xcode project.** The project uses
`PBXFileSystemSynchronizedRootGroup`, so anything dropped into that folder is compiled
automatically. This is why the file is enough on its own.

It stays untracked — `.gitignore` already covers it. Keep it that way.

### Signing

`project.pbxproj:307` has `DEVELOPMENT_TEAM = ""`. In Xcode:

**Target → Signing & Capabilities → Team** → pick your team. Leave "Automatically manage
signing" on.

### Decide on the bundle identifier — before you ship anything

Currently `app.rork.kffuebxmbishdc4eli446` (`project.pbxproj:418`). That is a Rork-generated
placeholder.

- If a build is **already registered in App Store Connect** under that ID, leave it. Changing it
  creates a different app.
- If you are **starting fresh**, change it now to something you own, e.g.
  `com.newlevelmarketing.modernbody`. A bundle ID is effectively permanent once submitted.

Tell me which, and I will note it in the brain.

## Phase 2 — Run it

1. Open `ios-calzy/ModernBodyFoodScanner.xcodeproj`.
2. Build for the **Simulator** first. This proves `Config.swift` is correct and signing is not in
   the way.
3. Then build to your **physical iPhone**.

The app is **iPhone-only and portrait-only** (`TARGETED_DEVICE_FAMILY = 1`), so do not be
surprised by no iPad target.

### Expected first-run behaviour

- Onboarding gates the app until completed.
- Camera permission is requested when you first open the scanner, not at launch.
- Purpose strings are already written and specific — no work needed there.

## Phase 3 — Confirm the AI actually works

Get the toolkit key from your **Rork project settings** and put it in `Config.swift`.

You will know immediately whether it is right, because of a fix already on the branch:

- **No key** → "AI scanning isn't available in this build yet."
- **Wrong key** → an auth error.
- **Correct key** → a real nutrition estimate.

Before that fix, a missing key produced *"AI features are currently unavailable. Please reload the
page"* — which told you nothing useful. Note the web fix is on the branch; **the same bug is still
live in `NutritionAI.swift:89-92`.** See "What I can do next".

## Phase 4 — The screen recording (Apple item 1)

The shot list is in `submission/app-review-information.md`, Part 2. Key points:

- **Physical device only.** Apple asks for it explicitly and can tell.
- **Delete and reinstall first**, so onboarding runs and the permission dialogs actually appear on
  camera. A recording that skips them will not satisfy the request.
- Let camera, photo library and notification prompts each appear on screen.
- Scroll the whole Settings list to show there is no paywall — that is the clearest answer to
  Apple's purchase-flow question.

Record it, and item 1 and item 2 both close.

## Phase 5 — Archive and upload

Needs the paid membership.

1. **Product → Archive** (with a real device selected, not a Simulator).
2. **Distribute App → App Store Connect**.
3. Fill the Notes field from `submission/app-review-information.md`, Part 1.
4. Attach the recording, and reply to the Guideline 2.1 message.

Before you submit, work through Part 3 of that document — the pre-send checklist. The two that
matter most: a live **Privacy Policy URL** and a **Support URL**. Both are solved by deploying the
web build, which needs no Mac.
